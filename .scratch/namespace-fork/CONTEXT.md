# Namespace 和实例元数据领域词汇

本词汇表统一本地架构讨论中的数据归属、复制和 fork 概念。它只定义领域含义，具体模块与接口设计见关联方案。

## Language

**Namespace**：拥有独立用户对象、SQL 对象元数据、配置和访问身份的逻辑空间。
_Avoid_：用 root 或系统空间泛指全部实例状态。

**Namespace SQL 对象元数据**：所属 Namespace 的数据库、表、列、索引、权限及其历史定义；SQL 依此识别和使用对象。
_Avoid_：仅用“目录”同时指代对象定义、实例控制记录和物理映射。

**Namespace 可继承状态**：fork 在确定快照继承的逻辑状态，例如用户数据与对象定义。

**Namespace 运行状态**：归一个 Namespace 所有的执行状态，例如任务占有和调度进度；其继承规则与用户数据分别定义。

**实例共享元数据**：同一数据库主备共享的持久控制状态；它不属于某个用户 Namespace，也不被 fork 继承。
_Avoid_：实例共享目录、归属不明的全局 schema。

**本机私有数据**：只属于一个运行实例的持久状态，不随数据库复制到备库。
_Avoid_：本机目录、用实例表同时指代共享和本机数据。

**逻辑 tablet**：Namespace SQL 对象元数据中标识一个数据分片的对象，可由不同 Namespace 使用相同本地编号。

**物理 tablet**：共享存储管理的确定数据对象；fork 可以在快照限制下引用同一物理对象。

**fork cap**：继承数据对该 fork 可见的最高快照边界。

**物化**：为一个 Namespace 建立自己的可写物理副本，并发布其逻辑到物理的归属关系。

**基线接管**：物化副本完成对继承数据的接管，读取不再需要访问源物理 tablet 对象。
_Avoid_：把物化完成直接等同于源依赖解除。

**历史依赖**：为了继续读取已确定的历史视图，一个 Namespace 或物化副本仍需要某个物理 tablet 及其快照数据的关系。

**物理布局**：解码和合并存储数据所需的列、行键、类型和原始默认值等信息。
_Avoid_：用 SQL schema 泛指物理布局及权限、表名等逻辑定义。

**快照 pin**：要求保留某个快照所需数据和元数据历史的持久引用。

**实例管理连接**：有实例管理身份、明确数据范围和操作权限的客户端连接；其身份不由 Namespace 编号推导。

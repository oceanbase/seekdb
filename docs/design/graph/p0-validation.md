- 独立 CTest 协议测试；ASan/UBSan 构建测试通过。受限环境下 LeakSanitizer 进程检查失败，使用允许该检查的执行环境重跑通过，没有关闭泄漏检查。
- graph.semantics、graph.transaction：通过现有 CI runner 的 discover_cases/run_case 执行；本地连接使用独立库和 root 测试账户。
- 现有 join_null mysqltest 通过。没有运行全量 SQL 回归。
- 7 类固定模式与独立 Python 穷举结果按多重集一致；10 个固定随机种子，每个覆盖 7 类模式、正反向单语句批量方案、正反向分页控制器。
- 页大小 1、2、64 的真实读库结果相同；重复绑定、平行边、缺失端点、复合键和空输入覆盖。
- 双连接固定快照、读自己的删除、回滚通过；真实图形关系查询收到 KILL QUERY 后报 1317，连接随后可以继续查询。
- 控制器故障注入覆盖源点查询、边查询、目标点查询、取消、rescan 和预算拒绝；这是协议级故障测试，不是存储引擎故障注入。

## 性能基线

合成图 1000 点、10000 边，种子 20260909；64 个输入绑定对应 16 个源点。每种 SQL 预热一次，再运行 3 次。分页控制器每次重新启动和建连，复用已预热的数据缓存；结果均完整读取。下表为墙钟中位数（ms）。

| 分布 | 普通一跳 SQL | 转换后一跳 SQL | 绑定 JOIN | 单语句批量候选 | 分页 64 | 分页 256 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| uniform | 199.449 | 187.409 | 20.537 | 17.025 | 27.053 | 22.543 |
| hub | 216.071 | 203.999 | 319.487 | 340.853 | 575.687 | 264.482 |
| converge | 180.008 | 199.259 | 19.198 | 20.194 | 34.257 | 26.063 |

**比较口径：**前两列查询全部有效边；后四列只展开输入绑定。只能在对应组内比较，不能用后四列较小的绝对时间宣称图查询加速。

EXPLAIN 显示单语句候选使用 incident 临时结果、use_batch=true 的 Nested Loop 和 gp_out 索引扫描；汇合图的目标点读取使用 TABLE GET。均匀图和热点图仍可能选择顶点全表扫描。这证明现有 SQL 优化器能选择访问方式，不证明底层只读取一次或 CBO 估算准确。

本次分页控制器在热点图上的开销较大，页大小显著影响 SQL 次数。P1 没有依据必须新增图专用 DAS 算子；P2 需要在进程内消除协议和重复查询开销后重新测量。

服务端 CPU 为整个进程的增量，包含后台工作；RSS 是 10ms 采样峰值，不是查询的精确内存归属。返回的边行数不是存储检查边数。该版本没有 oceanbase.GV$OB_SQL_AUDIT 视图，因此没有用该视图补造读取计数。

## 仍需补齐的验收项

- 目标源码版本的服务端构建及回归；当前运行证据来自上述已有二进制。
- Oracle/DuckPGQ 的二进制语法兼容验证，当前仅完成官方文档核对和契约用例。
- 直接 DAS 迭代器适配、语句快照继承、查询 allocator 预算、实际存储检查行数。客户端 RR 事务和额度估算不能替代这些验证。

因此本交付是可运行的 P0 契约与原型验证包；不将它标记为完整内核接入验收通过。后续职责和任务见 [架构与验收边界](p0-architecture.md)。

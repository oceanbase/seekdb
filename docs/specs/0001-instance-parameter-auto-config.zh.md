# 将实例参数持久化到自动配置文件中

> 本文件是 [0001-instance-parameter-auto-config.md](0001-instance-parameter-auto-config.md) 的中文翻译；如有歧义，以英文原文为准。

## 问题陈述

实例参数（instance parameter）是针对某个 seekdb 实例声明的设置，区别于 SQL 会话系统变量。目前 seekdb 将已保存的实例参数值存放在 SQLite 中。运维人员需要一种更简单的、部署本地（deployment-local）的表示形式，同时保留 seekdb 现有的参数行为，并确保写入过程中的崩溃不会留下写了一半的配置文件而导致无法重启。

## 方案

将已声明实例参数的持久化覆盖值存放于 `<base_dir>/etc/seekdb.auto.conf`，其中 `base_dir` 是实例部署目录。每次更新都通过 PostgreSQL 的持久化临时文件加重命名协议整体替换该文件。文件存储由 Rust 实现；C++ 继续负责参数校验，并管理 SQL、实例生效值和重载。运维人员可以在 seekdb 停止时查看或编辑该文件。保存的变更在参数允许的情况下会立即重载，而重启则会读取已保存的覆盖值。

## 用户故事

1. 作为运维人员，我希望已保存的实例参数位于部署目录的 `etc` 目录下，这样每个实例都携带自己的配置。
2. 作为运维人员，我希望该文件只包含已声明实例参数的值，这样其内容含义清晰。
3. 作为运维人员，我希望文件缺失即表示没有保存任何覆盖值，这样新实例从已声明的默认值启动。
4. 作为运维人员，我希望以 `name = 'value'` 形式读取每个已保存的值，这样无需 SQLite 工具即可查看配置。
5. 作为运维人员，我希望值中的引号和反斜杠能正确往返，这样已保存的值不会因序列化而改变。
6. 作为运维人员，我希望在实例停止期间可以添加空行和 `#` 注释，这样我能为离线编辑添加说明。
7. 作为运维人员，我希望不支持的文件语法能让启动失败并给出行号，这样格式错误的编辑可见。
8. 作为运维人员，我希望未知的参数名能让启动失败并给出该名字和行号，这样拼写错误不会被静默忽略。
9. 作为运维人员，我希望无效的参数值能让启动失败并给出该名字和行号，这样实例不会带着非预期的值运行。
10. 作为运维人员，我希望重名时以最后一次出现为准，这样离线编辑的结果可预测。
11. 作为运维人员，我希望下一次自动重写会合并重复的名字，这样生成的文件中每个参数只有一条记录。
12. 作为运维人员，我接受自动重写会丢弃离线注释，这样生成的文件遵循 PostgreSQL 的重写行为。
13. 作为 DBA，我希望 `ALTER SYSTEM SET` 保存该值并立即走 seekdb 的重载路径，这样变更行为保持熟悉。
14. 作为 DBA，我希望 `ALTER SYSTEM RESET` 移除已保存的覆盖值，这样对于动态参数，已声明的默认值即刻生效。
15. 作为 DBA，我希望 `SHOW PARAMETERS` 报告实例生效值，这样它反映运行中的实例实际使用的值。
16. 作为 DBA，我希望已保存的静态参数在重启后生效，这样 `SHOW PARAMETERS` 不会把未应用的值显示为已生效。
17. 作为 DBA，我希望成功保存后若重载失败，能明确说明该值已保存但无法应用，这样我清楚重启后会读到什么。
18. 作为 DBA，我希望设置多个实例参数的命令保持 seekdb 原有的逐参数顺序，这样在某个参数完成后崩溃时，已完成的该前缀仍被保存。
19. 作为运维人员，我希望启动命令行参数的变更被写回，这样在后续不带这些选项启动时它们仍然保持保存状态。
20. 作为运维人员，我希望诸如服务创建时间和角色信息之类的已声明内部设置使用同一套存储，这样当前内部行为得以延续。
21. 作为运维人员，我希望进程内的并发保存能在“读取到替换”的整个序列上串行化，这样一个写入者不会丢弃另一个写入者已完成的变更。
22. 作为运维人员，我希望保存期间崩溃只会留下完整的旧文件或新文件，这样下次启动绝不会读到部分写入。
23. 作为运维人员，我希望启动时忽略遗留的临时文件，这样被中断的保存不会改变生效配置。
24. 作为运维人员，我希望替换后目录同步失败时如实报告，而不谎称已回滚，这样不确定的持久化状态是明确的。
25. 作为受支持平台上的运维人员，我希望获得崩溃安全的替换操作，或者得到明确的构建期或启动期失败，这样实现绝不会静默截断在线文件。
26. 作为运维人员，我希望新建的配置文件仅限实例属主访问，这样已保存的设置不会暴露给其他本地用户。
27. 作为 seekdb 维护者，我希望其他元数据继续使用 SQLite，这样本次变更的范围仅限于实例参数持久化。

## 实现决策

- 范围仅限已声明的实例参数。SQL 会话系统变量和租户参数属于独立的问题域。
- 替换 SQLite 作为实例参数存储，但不迁移已有的已存参数值。其他 SQLite 元数据保持不变。
- Rust 负责解析、序列化、进程内写锁和持久化文件替换。C++ 负责声明、值校验、SQL 处理、运行时配置和模块重载。语言边界传递的是名字、值、来源行号和结果，而不是 C++ 配置对象。
- 启动时，解析完整快照，校验每一条记录，然后将该快照发布到运行时配置。出错时不得留下部分应用的快照。文件缺失时提供空的覆盖值集合。
- 读取方接受规范的带引号赋值、空行和 `#` 注释。写入方将单引号和反斜杠翻倍，每个名字只写一次，并省略注释。重复赋值以最后一条为准。
- 一次保存从读取当前文件到替换完成期间始终持有进程内锁。它把完整结果写入同目录下的临时文件，对其执行 sync 并关闭，对已存在的目标文件执行 sync，原子替换目标文件，然后对新目标文件和父目录执行 sync。在线文件绝不会被就地截断。
- 替换之前的失败使旧文件仍具权威性。遗留的临时文件被忽略。替换之后的失败报告为失败，且不声称持久的究竟是完整的旧版本还是新版本。
- SQL `SET` 先持久化，再立即重载。若重载失败，保留新的持久化覆盖值，并报告“已保存但未应用”。SQL `RESET` 移除覆盖值，并对动态参数立即恢复已声明的默认值。
- 对于更改多个实例参数的 SQL 命令，保持逐参数持久化；不存在命令级的文件事务。保留启动选项写回。`SHOW PARAMETERS` 继续显示实例生效值，对于静态参数在重启前仍显示旧值。
- 保留受支持的平台。缺少所需崩溃安全替换能力的平台必须在构建期或启动期失败，而不是退化为就地写入。新建文件仅实例属主可访问。

## 测试决策

- 使用一个主要接缝：一个已部署的 seekdb 实例，通过 SQL、启动选项、停止/重启以及部署本地配置文件来驱动测试。测试断言返回的错误、生效值、文件内容和重启行为，而不是 Rust 或 C++ 的调用序列。
- 扩展既有的 obtest 风格，该风格已经会设置多个参数并停止、重启实例。既有的 mysqltest 配置用例为 SQL 结果断言提供了先例。
- 覆盖 `SET`、`RESET`、动态值与静态值、启动写回、文件缺失、已声明内部参数、重复记录、注释、无效语法、未知名字、无效值，以及引号/反斜杠往返。
- 压测并发保存，并验证所有已完成的变更都能存活。对于在参数之间被中断的多参数命令，验证已完成的参数前缀仍被保存，且每一个观察到的文件都是完整的。
- 在临时文件同步、替换、新目标文件同步和目录同步前后注入故障或终止实例。在每个点之后重启，并断言文件解析结果恰好是一个完整的旧版本或新版本；在进程存活的情况下断言所报告的结果。
- 在成功保存后强制重载失败，验证“已保存但未应用”的响应、被保留的覆盖值，以及 `SHOW PARAMETERS` 显示的生效值。
- 针对持久化替换能力和仅属主可访问的权限，运行平台相关的构建与启动检查。

## 不在范围内

- 旧 SQLite 存储中参数值的迁移或向后兼容。
- 多参数 SQL 命令的事务性回滚或全有或全无的持久化。
- 在 seekdb 运行期间由外部进程进行的并发编辑。
- PostgreSQL 完整的配置语法或其延迟重载语义。
- 对 SQL 会话系统变量、租户参数或无关 SQLite 元数据的修改。

## 补充说明

本规范遵循已提出的实例参数自动配置 ADR 以及仓库中的实例参数术语表。PostgreSQL 的 `AutoFileLock` 是一种内部共享内存锁；seekdb 使用进程内写锁，因为约定的部署模型中只有一个进程写入其实例文件。持久化替换协议解决的是配置文件被撕裂写入的问题，而不是 SQL 事务原子性。

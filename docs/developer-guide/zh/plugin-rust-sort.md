# Rust 排序：从读取元数据到替代原生 SORT

日期：2026-09-10。生产重建、完整 kernel、动态库审计、独立 CTest 与
Rust 单测已通过；具体范围见文末，不借用 v16 结果作为本轮证明。

本页记录 v17 检查点。v18 进一步通过 [计划边界值](plugin-plan-values.md)
处理聚合／窗口结果与延后 SELECT 计算，其验证状态单独记录。

## 实际替换路径

v17 upper-policy 对支持的 SORT 提交 fragment：目标是 SORT 结果，
唯一输入是其原子树。私有 SSO1 计划描述输入键槽、方向、NULL 位置
及独立输出映射，不保存规划回调的表达式 ID。宿主按已有通用片段
协议完成正常属性、表达式分配、codegen 和执行，无新增内核排序算法。

算法和规划策略都在 Rust。原生 SORT 不再执行该节点的排序；插件
将排序键和输出数据变成 owned 行，再排序并发布结果。测试必须
检查真实物理计划，而不把 SORT 上方的 spool 误认为算法替代。

贡献仍然是 additive/Around：不 select，不伪造负代价。代价是参考
O(n log n) 模型，不是生产校准结果；宿主保留原生候选。现有上层
spool 作为不支持情形的参考回退保留，不改变聚合／窗口等原生语义。
注册仍是五个服务／七个扩展，没有第二套 runtime 或 loader。

## 当前策略与布局边界

- 本地串行、普通全排序；支持多整数键、ASC/DESC、NULLS FIRST/LAST。
  原生 encoded keys 只是表示优化，可以用已有规范化未编码键替代。
- prefix、partition、local merge、WITH TIES、Top-N、Top-K、hash 与
  runtime filter 不被误当作普通排序；当前策略不替换这些语义。
- 键须符合规范化 builtin integer／scalar deterministic 条件。
  不以字节序替代文本 collation、opaque 比较或浮点 NaN 语义。
- 保留实际排序键及其身份，即使它们不在 SELECT 中。SELECT 的直接
  列可以作为任意类型的载荷传递；重复目标去重，常量不申请可写槽。
  SELECT 表达式如果正是已有排序键，可以沿用其已求值的结果。
- 其他 SELECT 计算当前不提前求值：把计算移到 SORT/LIMIT 之前可能
  改变错误或副作用。全查询 column inventory 也不等于聚合／DISTINCT
  后的输入 schema，不能盲目要求已经不可用的底层列。

这些是参考策略的已知限制，不是通用 builder 或执行器的能力上限。
后续需要阶段感知的需求／可用值协议，保留 aggregate/window/DISTINCT
边界上的已求值结果，并让其他计算保持原求值位置；不能仅按关系 ID
包含关系推断物理可用性。当前不会以 SQL 文本匹配限定输入表或函数。

## 执行、取消与资源

键转为 Option<i128>，覆盖有符号和无符号整数极值；NULL 位置独立
于降序反转。按多键词典序比较，完全相等时按输入序号稳定打破平局。
使用可失败的原地堆排序，O(n log n)，排序阶段不分配额外数组；每
256 次比较检查取消，读取及输出也检查。错误不发布部分排序结果。

载荷按真实 type ID 与字节内容拥有，NULL 与空字节区分；输入 buffer
复用不影响排序结果。输出映射独立于输入布局。取第一行前检查键与
完整输出 schema，空输入也不能绕过校验。

本参考实现最多 65,536 行，owned 行／键／载荷及所计元数据预算为
16 MiB，超限返回内存错误，不静默截断。分配使用 try_reserve，排序
数组按固定块增长；预算不代表 allocator、宿主 Datum 或进程 RSS 的
总上限。当前无 spill，不是生产大数据排序已经完成。

取消／错误后游标由既有运行时失败状态约束，整体重扫清理 owned 行
和位置，宿主重扫输入；关闭释放状态。GIS 继续使用 C++。

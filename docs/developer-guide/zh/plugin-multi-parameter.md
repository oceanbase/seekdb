## 本次开放的能力

原先参数化片段只能替换一个根 Nested Loop JOIN，固定来源输入 0、
目标输入 1。本次把规划、物理值映射与 Rust 执行一起推广：

- 片段可承接多个被移除 JOIN 的完整 NestedLoop 参数列表。
- 每个 owner 的整个右侧消费者子树保留为一个输入；其左侧可以拆成
  多个不重叠的输入，包括展开更内层 JOIN。输入的物理序号不必等于
  原 JOIN 顺序或执行顺序。
- 一个目标可以接收不同来源的参数，一个来源可以供给不同目标；
  每个参数仍只有一个 owner 和一个目标。参数图必须无环。
- C++ 为每个来源独立保存 Datum 快照和 payload 计数，并按 Rust 返回
  的行/绑定失效集合清理。推进中间输入不会清除仍有效的祖先快照。
- Rust 参考执行计划 SJD1 显式提供拓扑调度、逐输入绑定/独立重扫选择
  和输出映射，按嵌套循环驱动真实子算子，至多保留每个输入一行。

例如原关系 `(A JOIN B) JOIN C`，内层参数来自 A、用于 B；外层参数
分别来自 A、B、用于 C。插件可以提交物理顺序 B、C、A，声明参数边
A → B、A → C、B → C，再以 A、B、C 顺序执行。C 的绑定要求 A、B
均有当前有效行，B 推进会使 C 失效，但 A 快照继续存活。

## 拥有权证明不依赖猜测消费者

宿主在被替代目标内部遍历，遇到保留输入根就停止：保留子树内部的
参数 owner 继续由原生算子管理。被移除 owner 的每个参数必须完整
交接，不能遗漏或重复；请求中的来源表达式须等于参数原来源，并且
来源输入必须位于原 owner 的左子树。仅表达式指针相同不足以证明作用域。

被移除部分当前限定为 JOIN 节点，其他节点可以完整保留为输入。
参数消费者暂时必须是原 owner 的完整右子树。这样无需从不完整的
只读表达式描述猜测参数消费位置，也不调用可能生成内部表达式的
get_op_exprs。拆分消费者、共享同一个参数的多个目标、above-pushdown、
跨查询块和非 JOIN owner 仍需专门协议，不能隐式放开。

普通 v3 片段也会检查已知参数 owner，防止绕过 v4 交接而丢失绑定。
该检查不代替任意 SQL 算法的等价性证明，插件仍须实现被替代关系语义。

## 物理表示与资源

原有 binding_sources 保存扁平来源槽；新增 binding_inputs 和
binding_targets 保存对应输入序号。它们随逻辑表达式、codegen 和物理
spec 传递，不保存规划调用期 ID。打开算子时检查数组长度、来源分区、
目标范围、参数槽唯一性及依赖环。

每次来源读取前先撤销旧快照，成功后才发布当前来源行。目标绑定只
更新属于该目标的参数；错误清理按失效集合覆盖部分写入。所有仍存活
的来源快照共享 16 MiB payload 上限，而不是每个输入各获得 16 MiB。
这仍不是完整租户 allocator 或生产资源调度体系。

Rust SJD1 使用独立的 16 MiB owned 行预算，NULL 来源也进入内层执行，
不套用等值 JOIN 的跳过 NULL 规则。空中间输入导致回溯推进祖先；EOF、
失败和整体重扫有独立状态。跨宿主回调只保存 owned 数据。

SJD1 是显式参考算法，不因支持重扫就宣称易变函数、远端服务或任意
输入可安全重复执行。在本检查点，默认 Rust planner 仍保留已有策略，
自动多层相关 SQL 候选尚未接入；后续接线与验证状态见本文顶部。

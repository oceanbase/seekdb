# Rust 输入依赖状态：就绪、绑定与传递失效

日期：2026-09-10。本文描述新增的内部运行时桥接，不是公开插件 ABI，
也不表示任意参数化计划已经开放。参数化请求与现有 SQL 路径另见
[参数化执行](plugin-parameter-execution.md)。

后续检查点已将实际参数拥有权和物理映射扩展到多个 JOIN、乱序输入
与多来源汇入，见 [多输入参数化](plugin-multi-parameter.md)。下文根
JOIN 的 0 → 1 描述保留本次状态迁移时的历史边界。

## 职责与实际接线

`rust/plugin-runtime/src/input_state.rs` 统一管理一个游标的输入行就绪、
参数环境就绪、传递失效和操作完成顺序。C++ `PluginCustomOp` 保留
Datum 快照、参数 setter、ParamStore、子算子与错误码转换；Rust 不保存
宿主值指针，也不调用插件或子算子。

物理执行器已改用 Rust 状态机进行 read / rescan / bind-rescan 准入，
替代原来的 source_ready / target_ready 布尔状态。现有实际图仍是输入
0 → 1：只接管被移除根 Nested Loop JOIN 的完整参数列表，保留原左右
子树。图算法通用，不代表规划拥有权校验或物理值映射已经通用。

独立、没有参数绑定的输入继续使用原路径，不为其额外建立状态句柄。
GIS 仍由 C++ 编写，运行时迁移不要求重写 GIS 算法。

## 状态契约

当前支持至多 64 路输入、4096 条边记录；重复边合并，自环和环拒绝。
构造时复制输入图，计算传递可达性；后续状态操作不分配内存。

| 操作 | 前置条件 | 开始时失效 | 成功完成 |
| --- | --- | --- | --- |
| READ | 有入边的输入必须已绑定 | 本输入及后代行；后代绑定 | ROW 发布当前行；EOF 不发布行 |
| RESCAN | 有入边的输入必须已绑定 | 同 READ，保留本输入入向绑定 | DONE 表示重扫完成，不表示已经有行 |
| BIND | 全部直接来源都有当前有效行 | 本输入及后代行、绑定 | DONE 才发布本输入的新参数环境 |

例如 A → B → C：A 推进会同时撤销 B、C；B 重扫保留来自 A 的绑定，
但撤销 C。多来源汇入 C 时，缺少任一当前来源行都不能绑定；不相关
分支不因别的分支推进而失效。来源 EOF 后可重扫，但必须重新取得行。

## 两段式宿主桥接

内部头文件为 `rust/plugin-runtime/include/plugin_runtime.h`，并未安装
到插件 SDK。输入边使用两个 u32；失效结果为 rows / bindings / ticket
三个 u64，分别表示行失效集合、参数环境失效集合和操作票据。

1. 宿主调用 begin，先应用返回的失效集合，再调用实际子算子或 setter。
2. 宿主操作期间没有 Rust 借用存活；句柄仍由这个游标独占、串行拥有。
3. 宿主调用 finish，提供原票据与 ROW / EOF / DONE / ERROR 结果。
4. 即使桥接返回错误，也要应用失效集合。集合不是仅包含此前有效的值，
   还覆盖可能部分写入的参数，防止错误清理遗漏。

票据跨整体重扫单调递增，不回绕；重复、错误、陈旧完成以及重入都会
使状态失败。ERROR 的桥接成功只表示已经记录宿主失败，不能把原本的
数据库错误转换成成功。C++ 保留原操作错误，并清理拥有的参数。

失败后只有成功的整体算子重扫才能重新开放状态；局部重扫不能消除错误。
reset 不执行子算子重扫，也不触碰 SQL 事务。close/destroy 撤销状态与
参数，释放 Rust 句柄。销毁要求没有宿主操作在执行，不是线程安全共享
句柄或异步完成 API。

## 验证范围

Rust runtime 124 项测试已重新通过，其中六项输入状态测试覆盖多来源、
多级依赖、无关分支、EOF、错误与重入、票据耗尽、64 输入边界和 FFI。
四输入图穷举检查全部 4096 个无自边有向图，通过独立 DFS 参考实现
识别 543 个 DAG，并比较其逐输入失效集合与剩余就绪状态。

新增 C++ host bridge 用例检查结构体大小及字段偏移，并通过真实链接
的 Rust archive 验证多来源、链式重扫、源数组所有权、陈旧完成和错误
恢复。CMake 与 Bazel 的 Rust 源码递归清单已包含新模块；kernel runner
的源码新鲜度门禁也增加该模块，避免新测试主程序链接旧生产状态实现。

首次生产构建发现 SQL 目标不包含裸 `plugin_runtime.h` 搜索路径；改用
现有仓库根 include 路径引用内部头文件后，生产构建通过（80365）。
SDK 119 项测试及 27 项 doc-test 重新通过。完整 kernel（21797）通过，
包含十八组多输入物理用例与十八组 JOIN SQL，覆盖相关 SQL 的原生与
真实 Rust 路径、两参数、NULL/字节/LOB 快照、取消和来源重扫等既有
矩阵。schema/session 与部分输入仍有夹具，不证明实库 catalog 或 PX。
独立测试集已重建（20989），30/30 CTest 通过（26462，108.73 秒），
包含新增的真实 C ABI 布局/图状态桥接、47 个原生执行协议变体、GIS
C++ 与 Rust loader、SDK、打包、脚手架和构建边界。生产宿主对应的
v12 Rust 插件重新构建并通过二进制审计（22104），十四项插件单测、
十二项构建门禁、格式和源码边界检查通过。Bazel 源码清单包含新模块，
但本轮没有执行 Bazel 或新增跨平台验证。

## 下一步仍需开放的能力

运行期依赖图与规划期参数拥有权是两层问题。下一步需要同时扩大：

- 从被替代子图识别参数的原 owner、来源和保留消费者，而非只读根 JOIN。
- 对多来源、多目标逐项保存物理 setter 与来源快照，并按失效集合清理。
- above-pushdown、跨查询块作用域与外部参数依赖的归属和恢复协议。
- 真正多级相关 SQL 的原生/插件等价性，部分 setter 失败、out-of-row
  LOB、计划缓存和 PX 的引用与资源生命周期。

不应只放宽请求的输入数量检查，就宣称通用参数化 DAG 已经可用。
其他规划阶段、成本、批量/spill、实库 catalog、类型/索引、AI 与轻量化
仍属于完整目标，不能用一个通用状态算法替代它们的实际内核协议。

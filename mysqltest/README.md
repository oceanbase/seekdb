# MiniVectorDB 公开基础用例

这是 `2026-competition-round2` 的首批公开 SQL 用例，用于明确基本操作和预期结果。通过公开用例不等于通过正式功能准入；正式测试还会覆盖其他输入、事务、持久化、恢复、索引维护与资源约束。

本目录只包含公开用例和预期结果，不包含参考数据库实现、隐藏负载、性能基线或 Agent 评分材料。

## 用例范围

| 用例 | SQL 数量 | 检查内容 |
| --- | ---: | --- |
| sql_crud | 9 | 建表、多行插入、查询、更新、删除、无匹配记录的修改 |
| sql_comparisons | 7 | 数值和字符串比较、AND 条件 |
| sql_ordering | 7 | 升降序、并列主键排序、LIMIT、无序结果 |
| sql_empty | 4 | 空表查询、空结果及空表删除 |
| vector_euclidean | 5 | 二维向量、向量更新、欧氏距离及精确距离排序 |

按 `manifest.json` 列出的顺序读取各用例。每个用例从独立的空数据库开始；用例之间重复使用 `docs` 表名是有意的，不要把所有文件连起来在同一个数据库执行。

## 文件格式

这是 **mysqltest 风格的 SQL/预期结果用例集**，不是 MySQL 官方 mysqltest 的可直接执行题包：

- `cases/<name>.test`：UTF-8，每个非空行是一条完整 SQL，按文件顺序执行。
- `cases/<name>.result`：JSON 数组，按 SQL 顺序逐条对应预期断言；不是 mysqltest 原生文本输出。
- `manifest.json`：公开用例清单与语句数量。

没有 `--source`、restart、crash 等驱动指令。不需要启动 MySQL 网络服务，也不能把 `VECTOR`、`L2_DISTANCE` 的语义替换为 MySQL 自身行为。本目录定义 SQL 输入和结果语义，进程通信的封装由配套测试驱动确定；不要将本目录误认为新的运行协议发布。

断言字段：

- `{}`：语句应成功，未额外限定其结果字段。
- `affected_rows`：受影响记录数，整数，必须精确一致。
- `columns`：查询列名数组，含别名，顺序必须一致。
- `rows`：查询结果行数组。没有 `unordered` 时按顺序逐项比较。
- `unordered: true`：按多重集合比较，忽略顺序但保留重复行数量。

查询字段出现时必须比较；不能将空 `{}` 解释为忽略执行失败。这里都是成功用例，数据库返回错误、退出或超时均不算通过。

## 关键语义

BIGINT 结果是整数，字符串按 Unicode 码点比较；普通排序并列时按主键升序。未指定 ORDER BY 的查询按预期中的 unordered 规则比较。LIMIT 0 返回空结果，LIMIT 大于记录数量时返回已有记录。

向量保存为 float32，L2_DISTANCE 是欧氏距离，不是距离平方。例如 `[3,4]` 到 `[0,0]` 的距离为 5。公开距离断言采用绝对和相对误差均为 `1e-5` 的浮点比较；整数、列名和字符串仍须精确匹配。

## 如何自测

1. 在 `2026-competition-round2` 实现数据库并准备 Dockerfile。
2. 对每个用例新建空数据目录，启动程序。
3. 逐行执行 `.test` 中的 SQL，将结果与 `.result` 同位置的对象比较。
4. 结束后清理本用例数据，再执行下一个用例。

这些样例不单独授分，也不代替正式准入、性能测试或 Agent prompt 评审。不要针对样例预存结果。组织方评测仓库中同名用例可通过 `run_case.py --case <name>` 单独执行；学生仓库不依赖该内部路径，本包不附带其完整驱动。
